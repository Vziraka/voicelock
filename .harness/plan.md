- [x] **Task 2** — `FakeStream` delivers frames through the REAL callback + a re-entrant-teardown tripwire
  - state: DONE
  - rejects: 0
  - files: `tests/test_capture.py`
  - notes: Test-harness only — **`capture.py` is not touched in this task.** This is
    the half of spec §1 item 2 that is provable at base: today `FakeStream` never
    invokes the callback it is handed (the word `callback` does not appear in the
    file), so `_on_audio` has **zero** coverage. That is why defect 1 shipped.
    `FakeStream` gains:
    (a) it keeps the `callback=` it was constructed with, and a `deliver(mono)`
        method that calls it the way PortAudio does — **2-D `(frames, channels)`**
        `indata`, plus `frames`, `time_info`, `status`;
    (b) it **stops delivering** once the callback raises `sd.CallbackStop`
        (mirrors PortAudio's contract);
    (c) a **re-entrant-teardown tripwire**: `stop()` or `close()` called while a
        callback is on the stack raises immediately.
    **Build note on (c) — this is not optional detail.** `capture.py:135-142`
    wraps both `stream.stop()` and `stream.close()` in `except Exception: pass`.
    A tripwire that raises a plain `Exception` is therefore **swallowed silently**
    and the regression test in Task 3 would pass while the defect is still
    present. Raise a **`BaseException` subclass** (e.g.
    `class ReentrantTeardown(BaseException)`) so it escapes the blanket handler
    and surfaces in the test. Verify this deliberately — a silently-swallowed
    tripwire is worse than none.
    Tests added here, both of which pass at base:
    - **callback carries audio** (spec §5 feature test 1): frames delivered
      through the real `_on_audio` — `pump()` never called — accumulate into
      `pcm_buffer()` and emit level frames. Proves `_on_audio` is exercised at all.
    - **the tripwire fires** (guardrail compliance): a callback that attempts
      teardown from inside the callback raises `ReentrantTeardown`. Without this
      test, branch (c) is a branch no test exercises — precisely the earned
      guardrail (`project.md` 2026-07-26) that cost F4 three REJECTs. This is
      testing the safety net on purpose, not gold-plating: the net is what turns
      Task 3's regression from a hung suite into a fast failure.
    **Deliberately NOT here:** any test that drives the capture past
    `max_seconds` through the callback. At base that path deadlocks (defect 1),
    so such a test cannot exit 0 in this task — it belongs to Task 3, which
    lands the fix and the regression together. A verifier reading this task
    should not score its absence as incomplete coverage.
    The existing pump-driven tests stay untouched (spec §3 non-goal: no broader
    test refactor — `pump()` is a real production path, `app.py:341-358` polls it
    every 50 ms).
  - done-criteria:
    - `uv run pytest tests/test_capture.py -q` → exit 0; final summary reports 0 failed. Must include the two new tests above (callback-carried audio with **no** `pump()` call; the tripwire raising), and every pre-existing pump-driven test (start/stop, level frames, mic error, 30 s cap, toggle) still passes unchanged
